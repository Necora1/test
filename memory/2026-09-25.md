### Lessons worth keeping

- **Script load order is load-bearing.** I first inserted `<script src="js/skin.js">` right after `config.js`; since `skin.js` destructures `Void.$` at init it threw, so `main.js` never reached `boot()` and the page stayed invisible with `is-booting` still set. It must load **after `core.js`** (last before `main.js`). Symptom to remember: blank stage + dock at `opacity: 0`, with *no* console error and a correctly-populated `Void`.
- **Headless `--virtual-time-budget` distorts CSS transitions.** A screenshot taken that way showed the toggle at `opacity: 0` and a blank page; a real-time CDP capture showed `opacity: 1` and every element fine. Don't trust virtual-time screenshots for animated/transitioning state — verify with real time.
- **Headless Chrome clamps `--window-size` width to ~500px.** My "360px" test silently ran at 500px. Use CDP `Emulation.setDeviceMetricsOverride` for true mobile widths.
- `--screenshot`/`--dump-dom` against `http://127.0.0.1` failed with ERR_CONNECTION_REFUSED partway through (my ad-hoc localhost server kept dying between exec sessions), and the `browser` tool refuses localhost by policy. Falling back to `file:///` URLs worked reliably — no server needed for static checks. Note the path needs `%20` for the space in `Runi's work`.
- **A `body::before` fabric layer + a class on `<html>` needs `html.no-fabric body::before`**, not `.no-fabric::before` — I got the selector wrong the first time.
- A hand-guessed Google Fonts woff2 URL (I invented a hash) returned 200 from `fonts.gstatic.com` but was not the real font, so the face silently fell back. Always pull the real URL from the `css2?family=` response and check the `src:` lines.

## Rennie: OBS audio monitoring + BlackHole routing fix (done & verified on-screen)

- renn's ask: monitor sound in their external headphones in OBS, but the **fifine mic was still going through OBS and coming out of BlackHole**. Then: "take over my screen and do everything."
- **Root cause is the key lesson: OBS monitoring is GLOBAL, not per-source.** There is ONE monitoring output for every monitored source, so you cannot use the monitoring device to separate mic from desktop audio. The fix belongs on the source. `Mic/Aux` (fifine) had `monitoring_type = 2` (Monitor and Output) in `basic/scenes/Untitled.json`, and the global monitoring device was `BlackHole2ch_UID` at launch. renn had already switched the monitoring device to External Headphones at 19:57 — the mic stayed monitored regardless.
- `Multi-Output Device` = BlackHole 2ch (**master**) + Razer Kraken V3 HyperSense, defined as `MetaDevice.~:AMS2_StackedOutput:0` in `/Library/Preferences/Audio/com.apple.audio.SystemSettings.plist`. BlackHole is a **loopback**, so anything monitored into it re-enters as an input — that is the feedback path. Rule: never monitor a loopback source.
- **Fix applied live via Accessibility, no OBS restart.** The authoritative control is the `AXMenuButton` titled `Monitoring Enabled` in Advanced Audio Properties (`OBSApp.OBSAdvAudio...QComboBox` at 1549,492 size 207x40) → set to `Monitor Off`. Evidence chain, in order of trustworthiness:
  1. OBS log: `User changed audio monitoring for source 'Mic/Aux' to: none`
  2. Scene file then `monitoring_type = 0`
  3. Combo title now `Monitor Off`
- **Trap I hit:** the mixer's own `AXCheckBox` with `AXDescription='Disable Monitoring'` read `value=1` while the source was *still actively monitored*. Only the Advanced Audio Properties combo reflected real state. When AX values disagree, let the OBS log arbitrate.
- **Second fix: fifine nominal sample rate 192000 → 48000 Hz.** It ran at 192 kHz against OBS's 48 kHz, causing 33× `Source Mic/Aux audio is lagging … at max audio buffering. Restarting source audio.` Setting the rate while OBS held the device open briefly threw `[input_callback]:[device 'fifine Microphone'] audio retrieval failed: -10863` (~1 s); **OBS recovered on its own**, meter came back live, and the lag spam stopped (last lag line 20:00:40, none after). **Rollback value if ever needed: 192000.**
- **Silence verified by measurement, not UI:** `ffmpeg -f avfoundation -i ":BlackHole 2ch" -t 6` → `mean_volume: -91.0 dB, max_volume: -91.0 dB`.
- Checked for other hijackers: only CoreAudio driver helpers (ARK, BlackHole2ch, VoiceEnhancer) + `arkauldiod`. **No Rogue Amoeba apps installed** (Loopback / Audio Hijack / SoundSource `.app`s absent; ARK.driver is just their shared escrow helper). Voice Enhancer and ParrotAudioPlugin drivers exist. `ffmpeg` present, no `sox`/`rec`/`sounddevice`.
- **Open question — asked renn, not assumed:** this scene collection has **no Desktop Audio source at all** (`DesktopAudioDevice1` absent from `Untitled.json`). So nothing is configured to send game/system audio to the headphones either. The wanted shape if renn wants it: Desktop Audio source with **Monitor and Output**, mic stays **Monitor Off**.

### Reusable helpers authored (in the macos-desktop-control skill dir)
- `obs_ax.py` — walk OBS's Qt AX tree, `find()` by role/desc/title, `press()`, `press_and_verify()`. Qt checkables/menu items carry `AXValue` 0/1 and respond to `AXPress`.
- `coreaudio_raw.py` — raw-ctypes CoreAudio device list + nominal sample-rate get/set (`python3 coreaudio_raw.py` / `... set <uid> <hz>`). Needed because **pyobjc's CoreAudio binding is broken on this box**: `AudioObjectGetPropertyDataSize` always fails `ValueError: argument 4 must be None or objc.NULL` regardless of arg form (struct vs byref, None vs objc.NULL). Use raw ctypes against `CoreAudio.framework`; selectors `'dev#'/'uid '/'nsrt'/'nsr#'/'lnam'`.
- Get device UIDs with `SwitchAudioSource -a -t output|input` (installed at `/opt/homebrew/bin`). `AXValueGetValue` lives in **`ApplicationServices`**, not `Quartz` — importing it from `Quartz` raises ImportError.
